Method chapter explainer

字段级差异先类型化，只对残留事实冲突做证据约束裁决。

当前最稳的创新定位是 triage before truth：从已经按 CVE-ID 对齐的 NVD-GHSA 记录对出发，先把每个目标字段转成可比较视图，再用确定性规则区分等价、表述差异、不完整、时间差异和事实冲突。只有事实冲突样本进入证据层，并保留拒判与人工审计接口。

三层流程

1. Field-view construction

抽取每个字段的 NVD/GHSA 原始值、来源 provenance、可比较表示和 rule-note carrier。severity 映射到规范标签；date 做时间戳规范化；references 做 URL/host 去重；CWE 做集合化；affected_versions 尽量转成 span-like 结构。

2. Deterministic discrepancy typing

按有优先级的字段规则输出五类工作标签。兼容解释先于 residual factual_conflict，这个阶段的目标不是选出正确来源，而是避免把所有二元不一致都错误地当成事实冲突。

3. Evidence-constrained source-support prototype

只对 sampled factual_conflict 激活。系统抓取 URL provenance、fetch status 和 advisory 文本片段，运行轻量 cue-matching baseline，并输出 provisional NVD、GHSA、both、neither 或 abstain。

操作合同与 Procedure

方法产物 必须保留的内容 用途 当前边界
Field view 原始值、规范化 comparands、来源 provenance、rule-note carrier。 支撑 RQ1 分布和 RQ2 typing audit。 规范化仍是 baseline 规则，不是已验证字段语义。
Typed instance 五类差异标签、规则说明、routing action。 决定 normalize、augment、interpret timing 或进入证据层。 没有 RQ2 gold 前不能报告分类性能。
Evidence context 候选 URL、URL provenance、fetch status、文本片段、source class。 支撑 evidence availability、silver diagnostic 和人工审计队列。 抓取片段不是人工核验过的页面重建。
Adjudication record NVD/GHSA/both/neither/abstain、matched cues、human-audit 字段。 当前用于 prototype 输出和后续 human-gold evaluator。 silver-v2 是 annotation aid，不是 evaluation oracle。

Procedure 1

遍历 CVE-aligned field instance，构造 field view，按字段规则顺序输出差异类型。EQ/RD/INC/TD 在 routing 层停止，不进入 source-support prototype。

Procedure 2

只处理 sampled FC：收集引用、抓取证据、匹配字段 cue，输出 source-support prototype，并把最终判断交给 human audit。

五类差异标签

Equivalent 规范化后字段事实一致，可以合并。
Representation 表述或 schema 不同，但规则判断事实兼容。
Incomplete 一侧缺失或明显为另一侧子集，优先补全而不是选边。
Temporal 发布时间或更新时间差异，更像流程时序问题。
Factual conflict 前四类都解释不了，才进入证据裁决。

差异类型决定下一步动作

差异类型 典型触发 下一步动作 当前验证边界
Equivalent 规范 severity、CWE 集合或版本 span 匹配。 合并或静默处理为非行动性差异。 确定性 baseline，等待 RQ2 gold 核验。
Representation 同日时间戳、标签别名、URL 或 range-shape 表述差异。 规范化表述并保留来源 provenance。 确定性 baseline，等待 RQ2 gold 核验。
Incomplete 一侧 reference、CWE 或 affected-version 内容缺失。 作为补全或覆盖差距处理，不直接选边。 确定性 baseline，等待 RQ2 gold 核验。
Temporal 跨日 published/date 差异。 解释为发布、导入或 enrichment 时序差异。 确定性 baseline，等待 RQ2 gold 核验。
Factual conflict severity 冲突或无法解释的版本结构残差。 进入证据层，允许 NVD、GHSA、both、neither 或 abstain。 RQ3 prototype，等待 human audit。

证据层如何解释当前 prototype

对象 当前实现 论文中可声明的内容
severity evidence_score_baseline 匹配 severity label、CVSS score 和 vector。 silver-label 上的 evidence-availability 与 baseline diagnostic。
affected_versions version_token_support_baseline 检查证据文本是否出现两侧版本 token。 audit-prioritization heuristic 与 token-support prototype，不是语义版本范围裁决。
source decision 输出 provisional NVD、GHSA、both、neither 或 abstain。 保留 both 和 abstain，避免强制 winner-only 裁决；最终有效性等 human audit。

相关工作边界

方向 输入与阶段 通常输出 证据与 abstention 本文边界
漏洞库质量与不一致研究 单库审计或跨源观察。 缺失、质量缺陷、severity 差异、版本范围困难。 多为描述性统计；source support 不是主要输出。 本文进一步把 CVE 对齐后的字段差异类型化，并定义 source-support handoff。
非结构化 advisory 差异挖掘 报告文本、advisory prose、抽取 aspect。 文本或 aspect-level inconsistency labels。 证据通常就是输入文本；abstention 通常不是一等输出。 本文从结构化 NVD-GHSA 字段对开始，输出字段类型与 routing action，不做文本 aspect discovery。
Truth discovery / data fusion 尚未经过字段 routing 的多源 claim。 真值估计或全局来源可靠性。 证据多隐含在来源一致性里；abstention 不是中心机制。 本文不学习全局 truth model；先排除非冲突字段差异，再对残留 FC 做证据约束 source-support。
Affected-version / scanner ecosystem 包名、range event、commit、scanner 输出。 适用性错误、scanner divergence、版本范围困难。 可使用 commits/advisories，但不是本文的 field-typing workflow。 本文当前保持 diagnostic-only，尚未声称语义版本范围裁决。

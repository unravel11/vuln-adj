# Vexed by VEX Tools：全文解析

**证据等级**：全文 PDF，19 页；arXiv:2503.14388，2025 预印本。

## 1. 论文一句话定位

论文比较多个容器漏洞/VEX 工具对同一镜像的报告一致性，追踪数据库选择、标识符和工具配置如何造成下游差异。

## 2. 论文要解决的问题

用户看到的是 scanner/VEX 输出，而不是原始数据库。不同工具使用不同漏洞源、标识符和匹配逻辑，导致同一镜像报告不同。gap 是缺少跨工具、同对象的一致性测量及原因分析。

## 3. 核心贡献拆解

旧综述记录 7 个工具、48 个镜像、最高 pairwise similarity 69.4%、五工具共同项 3.4%，以及数据库因素相关系数 0.88；这些是论文设置下的描述/关联，不能写成数据库差异造成工具差异的因果效应。全文可确认其有工具矩阵、标识符映射和影响因素分析。

## 4. 方法揉碎讲解

固定镜像输入各工具，规范化报告中的 vulnerability identifiers，再计算集合相似度/交集并关联工具数据源与配置。规范化模块决定 GHSA/CVE/Snyk alias 是否被视为同一漏洞；若 alias map 不全，一致性会被低估。假设包括扫描时间可比、数据库快照接近、工具配置公平。

## 5. 实验逻辑

主实验回答工具输出有多不同，后续分析检验数据库、标识符和配置因素。它直接连接“上游元数据差异”与“下游安全工具工作量”，但不是字段 type-first routing 的受控 A/B 实验。

## 6. 论文真正证明了什么

强结论是所测工具在固定样本上的报告差异很大。中等结论是数据源和 identifier mapping 与差异显著相关。它不证明具体字段冲突的真值，也不证明改用某一数据库能消除差异。

## 7. 局限与风险

工具版本、在线数据库、扫描时点和镜像集会漂移；相关性不等于因果。VEX 输出还包含 reachability/产品语义，不能全部归因于 NVD/GHSA。

## 8. 可复述版本

10 秒版：数据库和标识符差异会出现在最终 scanner 报告里。组会版：这给 T2 的实践动机，但 T2 必须直接测路由工作量，不能借用其相关系数代替。

## 9. 对本项目的可迁移点

可借鉴集合规范化、alias audit 和工具级 outcome。可把“unnecessary escalation/遗漏 conflict”解释为 curator 侧对应的 downstream 成本，但需本项目自己的真人或明确 action oracle。

## 10. 审稿式评价

**Strengths**：实务影响清楚、工具比较直观。**Weaknesses**：快照/配置敏感，因果识别有限。**Questions**：统一数据库与 alias map 后还剩多少工具机制差异？

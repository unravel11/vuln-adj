# 跨来源漏洞严重性不一致：全文解析

**证据等级**：全文 PDF，11 页；SANER 2022；arXiv:2112.10356。代码与数据由作者公开。

## 1. 论文一句话定位

论文沿 Firefox 漏洞报告生命周期比较 Bugzilla、Mozilla advisory 与 NVD 的严重性等级，并测试来源选择如何影响优先级和严重性预测。

## 2. 论文要解决的问题

严重性是人工、阶段相关且带主观性的判断。同一漏洞在初报、厂商公告和数据库阶段可能被不同人员、不同量表赋值。论文不只问“是否不同”，还问差异与哪些属性相关，以及把不同来源当标签会怎样改变下游模型。

## 3. 核心贡献拆解

可确认贡献包括：对单一大型项目的三阶段 severity 数据做一致性测量；分析潜在相关因素；用不同来源标签训练/评估预测任务。摘要报告下游性能最多下降 77%，这是特定数据划分、标签映射和预测设置的结果，不能外推为所有项目或所有 downstream task。

## 4. 方法揉碎讲解

作者先以漏洞身份把三个来源关联，再把不同 severity scheme 映射到可比较等级；随后计算等级关系、早期低估现象与属性关联；最后交叉使用不同来源作为训练或测试标签。映射让比较可执行，但会压缩原量表语义。隐含假设包括 Firefox 报告链可正确连接、映射保留关键排序、较晚来源不自动等于真值。

## 5. 实验逻辑

RQ1 描述不一致形态，RQ2 分析与错判相关的属性，RQ3 测量标签来源对预测性能的影响。这比只报告差异率更接近“决策效用”证据，但效用对象是 severity prediction，不是人工裁决工作量。统计关联也不能被写成导致错判的因果机制。

## 6. 论文真正证明了什么

强结论是 Firefox 三个来源的 severity 并非可互换。中等结论是初期报告在该样本中常出现较低等级，标签源选择能明显改变模型评价。它没有证明哪个来源逐例正确，也没有证明跨项目普遍规律。

## 7. 局限与风险

单项目、异构量表映射、时间阶段混杂和标签无独立 gold 是主要限制。作者分析的是严重性一个字段；对日期、references、affected_versions 的结论不能由此推出。

## 8. 可复述版本

10 秒版：同一漏洞在三个生命周期来源中的 severity 会不同，而且标签源选择会改变下游模型。组会版：它给了“差异会影响行动”的范式，但没有给出 type-first routing 或可靠来源裁决。

## 9. 对本项目的可迁移点

最可迁移的是 T2 设计逻辑：不能只证明分类存在，还要比较不同路由策略对 workload、遗漏与无效升级的影响。不可把其 77% 直接当作本项目收益预期。

## 10. 审稿式评价

**Strengths**：把数据质量连接到 downstream consequence。**Weaknesses**：项目和字段范围窄，来源阶段与来源身份难分。**Questions**：若按发布时间做同阶段比较，结论是否保持？

# Expert-Candidate Validation

This experiment evaluates isolated AI security-expert candidate labels. It never treats them as human-gold.

Expected raw inputs are generated by `scripts/run_expert_candidate_annotation.py` under `data/annotations/expert_candidate/raw/`.

The evaluator reports:

- RQ2 deterministic-baseline performance against the candidate labels.
- Same-model repeatability on the 20% RQ2 review sample.
- RQ3 baseline agreement against candidate source-support decisions.
- RQ3 candidate agreement with the existing `silver_v2` pass.

All output manifests set `label_is_human=false` and `author_review_required=true`. These metrics may be used for diagnostics and deciding what to inspect next, but not as human-gold paper results.

Run on the authoritative remote:

```bash
python3 experiments/expert_candidate_validation/evaluate_expert_candidate_labels.py --allow-partial
python3 experiments/expert_candidate_validation/analyze_candidate_coverage_and_priority.py
python3 scripts/build_expert_candidate_review_packets.py
python3 experiments/expert_candidate_validation/validate_human_review_packets.py
```

RQ2 generation defaults to `round-robin-field` scheduling so partial runs do not remain confined to one field. Preview the resume plan without calling the API:

```bash
python3 scripts/run_expert_candidate_annotation.py \
  data/annotations/rq2/discrepancy_typing_seed.jsonl \
  --task-kind rq2 \
  --pass-id primary_v2 \
  --output-path data/annotations/expert_candidate/raw/rq2_primary.jsonl \
  --resume --plan-only
```

Use `--max-new-rows` to cap a resumed API run after completed-ID filtering and field balancing.

Review packets under `data/annotations/expert_candidate/review_packets/` are isolated handoff artifacts. The readiness validator exits nonzero with `--require-signed` until at least one row has valid human annotator, independent reviewer, author sign-off, and timestamp fields.
